## 1. UX АУДИТ (Анализ как система обучения)

---

### A. Ранжированные UX-проблемы

---

#### [КРИТИЧНО] P1. Отсутствие авто-продвижения после ответа

**Описание.** После нажатия VERO/FALSO кнопки блокируются, подсвечивается правильный/неправильный ответ, но **страница не делает ничего**. Пользователь должен вручную нажать кнопку перевода, кнопку комментария или кликнуть на пагинацию.

**Root cause.** В `handleAnswer` нет никакой логики продвижения. `answer()` обновляет состояние, но движение к следующему вопросу — отдельное действие пользователя (свайп или клик по кружку).

**Где в потоке.** `QuizPage.jsx → handleAnswer → useQuiz.answer()` — после этого ничего не происходит.

**Влияние на обучение.** Пользователь после ответа находится в когнитивной паузе — система не даёт ему направления. Момент максимального внимания (сразу после ответа) тратится на навигационный выбор, а не на усвоение информации.

---

#### [КРИТИЧНО] P2. Комментарий (объяснение) — опциональный и скрытый

**Описание.** Комментарий доступен только по нажатию иконки 💬 (`action-icon`). Кнопка видна всегда, но CommentAccordion рендерится только если `showComment && currentAnswer !== undefined`. После перехода к следующему вопросу `showComment` принудительно сбрасывается в `false` (`setShowComment(false)` в `handleGoTo` и `handleAnswer`).

**Root cause.** Комментарий трактуется как вспомогательная фича ("если интересно"), а не как обязательная часть обучающего цикла.

**Где в потоке.** `CommentAccordion` → условие `isVisible={showComment && (currentAnswer !== undefined || isFinished)}`.

**Влияние на обучение.** Нарушается принцип **elaborative interrogation** (объяснение *почему* ответ именно такой критически важно для долгосрочного запоминания). Пользователь видит факт ("ошибся"), но не получает обязательного объяснения. По данным Roediger & Karpicke (2006), обратная связь без объяснения дает ~40% от потенциала retention.

---

#### [КРИТИЧНО] P3. Нет разграничения между "просмотром" и "ответом"

**Описание.** Пользователь может freely навигировать через пагинацию по неотвеченным вопросам, визуально сканировать их и принимать решение о стратегии. Кнопки VERO/FALSO заблокированы только если вопрос **уже** отвечен — но не мешают "подглядывать" на другие вопросы перед ответом.

**Root cause.** `goTo()` позволяет перемещаться к любому вопросу без ограничений. Блокировка кнопок проверяет только `currentAnswer !== undefined`, не состояние навигации.

**Где в потоке.** `QuizPagination → onSelect(index) → handleGoTo(index)` — нет guard'а.

**Влияние на обучение.** Поощряется **поверхностная стратегия**: пользователь может "пройтись" по всем вопросам, составить план ("этот похож на правду, этот — нет"), что убивает **retrieval practice effect** — главный механизм усвоения при тестировании.

---

#### [ВЫСОКИЙ] P4. Кнопка VERIFICA заблокирована пока не отвечены все вопросы

**Описание.** `pagination-item--finish disabled` — кнопка завершения неактивна и некликабельна если `!isFinished`. Пользователь не может завершить и посмотреть результат, пока не ответил на все 30 вопросов.

**Root cause.** `isFinished` в `useQuiz` становится `true` только когда `results.length === questions.length`, а VERIFICA вызывает `finish()` отдельно.

**Где в потоке.** `QuizPagination → pagination-item--finish → onClick={() => isFinished && onFinish()}`.

**Влияние на обучение.** Создаёт принуждение "ответь на всё" вместо возможности ранней рефлексии. Минорная проблема — но ломает поток в случае, если пользователь хочет остановиться в середине.

---

#### [ВЫСОКИЙ] P5. ResultScreen: нет детального разбора ошибок

**Описание.** `ResultScreen` показывает только: `correctCount`, `wrongCount`, `scorePercent`, статус passed/failed. Нет списка неправильных вопросов, нет возможности сразу перейти к разбору конкретной ошибки.

**Root cause.** `results` передаётся в компонент, но используется только для подсчёта `correct/wrong`. Поле `questionId` и `topicId` в каждом результате не используются для навигации.

**Где в потоке.** `ResultScreen.jsx → results.filter(r => r.correct).length` — это единственное использование массива результатов.

**Влияние на обучение.** Нарушается **error correction loop** — пользователь видит "вы ошиблись 7 раз", но не знает в чём именно. Переход в /errors требует новой навигации и новой загрузки данных.

---

#### [СРЕДНИЙ] P6. Перевод (globalTranslation) — глобальный переключатель

**Описание.** `globalTranslation` — булевое состояние в `QuizPage`, которое применяется ко **всем** вопросам одновременно и сохраняется при навигации. Нет per-question control.

**Root cause.** `setGlobalTranslation(prev => !prev)` в `handleToggleTranslation` — глобальный стейт.

**Где в потоке.** `QuestionCard → showTranslation={globalTranslation}`.

**Влияние на обучение.** Если пользователь включил перевод для одного сложного вопроса — он навсегда включён для всех. Теряется **context-specific difficulty**: некоторые вопросы понятны без перевода, другие — нет. Пользователь либо читает всё на русском (снижая языковую нагрузку/обучение), либо вообще не использует перевод.

---

#### [СРЕДНИЙ] P7. Нет визуальной индикации прогресса внутри сессии

**Описание.** QuizPagination показывает 30 кружков с цветами, но нет текстового "Вопрос X из 30" и нет прогресс-бара самой сессии. Пользователь должен считать кружки.

**Root cause.** Пагинация — единственный индикатор. `QuizPage` не отображает `current + 1 / questions.length` в header или под пагинацией.

---

#### [НИЗКИЙ] P8. answeringRef debounce = 50ms — возможна потеря клика

**Описание.** В `useQuiz.answer()`: `setTimeout(() => { answeringRef.current = false; }, 50)`. Защита от двойного клика, но 50ms — очень короткое окно. На iPad mini 2 с лагом тач-событий пользователь может легитимно нажать дважды (tap bounce) и получить игнорирование второго нажатия без какого-либо feedback.

---

### B. Анализ влияния на обучение

| Проблема | Нарушенный когнитивный принцип |
|---|---|
| P1: нет движения после ответа | Testing Effect — момент максимального внимания теряется |
| P2: скрытый комментарий | Elaborative Feedback — без объяснения нет глубокого кодирования |
| P3: свободная навигация до ответа | Retrieval Practice — пользователь "стратегизирует" вместо честного воспроизведения |
| P5: нет разбора ошибок | Error Correction Loop — ошибки записаны, но не проработаны в моменте |
| P6: глобальный перевод | Desirable Difficulty — убирает полезное когнитивное усилие |

---

### C. Скрытые точки трения

**C1. Кнопка комментария неактивна до ответа, но всегда видна.** `disabled={currentAnswer === undefined && !isSessionFinished}` — кнопка серая и некликабельна перед ответом. Пользователь нажимает → ничего не происходит. Нет tooltip, нет объяснения почему. Создаёт тихое недоумение.

**C2. Свайп и пагинация — дублирующие механизмы без явной иерархии.** Оба делают одно и то же. На iPad это нормально, но создаёт ситуацию когда пользователь случайно свайпает при попытке скроллить список вопросов в пагинации (touchmove vs swipe).

**C3. `showComment` сбрасывается в `handleAnswer`, но это не нужно.** Строка `setShowComment(false)` в `handleAnswer` означает что, если пользователь открыл комментарий предыдущего вопроса и нажал VERO/FALSO — комментарий закрывается. Но `handleAnswer` вызывается только для текущего вопроса, а `showComment` всё равно сбросится при `handleGoTo`. Это избыточный reset.

**C4. `ConfirmationModal` при выходе** — "Ваш прогресс будет потерян." Это правда, но пугает. Формулировка не объясняет что именно потеряется (отметки ошибок уже записались в `qp_errors` к этому моменту!).

---

### D. Упущенные возможности

**D1. Нет немедленной обратной связи после ошибки.** Когда пользователь ошибается, система просто красит кнопки. Нет никакого "стопа" — ничто не говорит "подожди, разберись почему ты ошибся". Самый ценный педагогический момент (сразу после неправильного ответа) никак не используется.

**D2. Нет паузы перед продвижением.** Testing effect усиливается когда есть небольшая задержка между ответом и следующим вопросом — достаточно 1-2 секунды чтобы мозг "закодировал" результат. Сейчас перехода нет вообще.

**D3. Ошибки записываются, но нет внутрисессионного цикла исправления.** `incrementError(q.id)` вызывается немедленно, но пользователь видит результат только при следующем заходе в /errors. Нет возможности "повторить ошибочные вопросы сейчас" внутри текущей сессии.

**D4. ResultScreen не использует данные `results`** для показа конкретных ошибок. Массив с `questionId` есть — он просто не рендерится.

**D5. Нет разграничения "тяжёлых" и "лёгких" ошибок.** `errorsService` хранит счётчик (`incrementError` / `decrementError`), но эта информация нигде не отображается пользователю. Вопрос с счётчиком 5 выглядит так же как вопрос с счётчиком 1.

## 2. НОВЫЙ ДИЗАЙН СИСТЕМЫ

---

### A. Новый обучающий цикл

Текущий цикл:
```
Вопрос → [ответ] → заблокировано → [навигация пользователя] → следующий вопрос
```

Предлагаемый цикл:
```
Вопрос → [ответ] → немедленная обратная связь (1s) → [если ошибка: принудительный комментарий] → авто-продвижение → следующий вопрос
```

Ключевые принципы нового цикла:

**1. Авто-продвижение с задержкой.** После ответа — 1.2s пауза (достаточно для фиксации результата), затем автоматический переход к следующему неотвеченному вопросу. Пауза используется для показа мгновенной обратной связи.

**2. Принудительный стоп при ошибке.** Если пользователь ошибся — авто-продвижение не срабатывает. Вместо этого CommentAccordion раскрывается автоматически. Следующий вопрос доступен только через явное действие ("Понял → Далее").

**3. Перевод — per-question, не глобальный.** Каждый вопрос запоминает собственное состояние перевода. Глобальный переключатель убирается.

**4. Навигация до ответа — ограниченная.** Пагинация кликабельна только для уже отвеченных вопросов. Для неотвеченных — только последовательное продвижение (или свайп к следующему неотвеченному).

---

### B. UX Flow (пошагово)

#### До ответа (Pre-answer state)
- Показывается вопрос с изображением
- Кнопки VERO / FALSO — активны
- Кнопка 💬 — скрыта (нет смысла до ответа, убираем тихий disabled)
- Перевод — кнопка 🇷🇺 активна, показывает перевод только этого вопроса
- Пагинация: неотвеченные кружки — кликабельны только если уже были посещены; строго вперёд-назад среди неотвеченных, свободная навигация — только по уже отвеченным

#### Сразу после ответа — правильного (Immediate positive feedback)
- Кнопки красятся: правильная — зелёная (✅)
- Маленький текстовый тег "Corretto!" появляется под кнопками
- **Таймер 1.2s** → авто-переход к следующему неотвеченному вопросу
- CommentAccordion НЕ раскрывается автоматически (чтобы не перегружать при правильном ответе)
- Кнопка 💬 — становится видимой, пользователь может открыть комментарий вручную (авто-переход в этом случае отменяется)

#### Сразу после ответа — неправильного (Error state — КРИТИЧЕСКИЙ)
- Кнопки красятся: выбранная — красная (❌), правильная — зелёная (подсказка)
- **CommentAccordion раскрывается автоматически**
- Авто-продвижение НЕ срабатывает
- Появляется кнопка "Понял → Далее" (явное действие для продвижения)
- Пользователь должен явно нажать "Далее" — это и есть принудительная рефлексия

#### После принудительного чтения комментария
- Пользователь нажимает "Понял → Далее"
- Переход к следующему неотвеченному вопросу
- `showComment` сбрасывается для нового вопроса

---

### C. State Model

#### Pre-answer state
| Параметр | Значение |
|---|---|
| Цель пользователя | Понять вопрос и дать честный ответ |
| Системный ответ | Показать вопрос + кнопки, заблокировать навигацию к неотвеченным |
| Поведение UI | VERO/FALSO активны; 💬 скрыта; навигация только к отвеченным |
| Когнитивная цель | Retrieval practice — попытка воспроизвести знание без подсказок |

#### Post-answer correct state
| Параметр | Значение |
|---|---|
| Цель пользователя | Получить подтверждение, двигаться дальше |
| Системный ответ | Показать ✅, запустить таймер 1.2s, предложить 💬 |
| Поведение UI | Авто-продвижение через 1.2s; таймер отменяется если открыт комментарий |
| Когнитивная цель | Positive reinforcement без задержки; лёгкость правильного ответа |

#### Error state (critical)
| Параметр | Значение |
|---|---|
| Цель пользователя | Понять ошибку |
| Системный ответ | Авто-раскрыть CommentAccordion; показать "Понял → Далее"; НЕ продвигать автоматически |
| Поведение UI | Заблокировать автопродвижение; кнопка-продвижение только через явный tap |
| Когнитивная цель | Elaborative feedback — объяснение ошибки в момент максимального внимания |

---

### D. Feedback Design

**Таймер авто-продвижения (правильный ответ):**
- Задержка: **1200ms** (не 500 — слишком быстро, не 2000 — раздражает)
- Визуализация: тонкая progress-линия под кнопками, заполняющаяся за 1.2s (CSS animation, один `div` с `width: 0→100%`)
- При открытии 💬 → `clearTimeout`, линия исчезает

**Ошибка — принудительный стоп:**
- CommentAccordion раскрывается через **150ms** после ответа (не мгновенно, небольшая задержка чтобы анимация кнопок успела отработать)
- Кнопка "Понял → Далее" появляется внутри CommentAccordion или под ним
- Стиль кнопки: фон `--color-wrong-bg`, текст "Понял → Далее →"
- Нет таймера — пользователь управляет темпом

**Текстовая обратная связь:**
- Правильно: маленький `span.answer-badge.correct` "✅ Corretto!" — под кнопками, 14px
- Неправильно: `span.answer-badge.wrong` "❌ Sbagliato!" — автоматически попадает в CommentAccordion (уже есть)

**Реализация таймера в QuizPage:**
```javascript
// Добавить в QuizPage
const autoAdvanceRef = useRef(null);

const handleAnswer = useCallback((userAnswer) => {
  answer(userAnswer);
  setShowComment(false);
  
  const q = questions[current];
  const isCorrect = userAnswer === q.answer;
  
  if (isCorrect) {
    // Авто-продвижение через 1.2s
    autoAdvanceRef.current = setTimeout(() => {
      const nextUnanswered = findNextUnanswered(questions, answered, current);
      if (nextUnanswered !== -1) handleGoTo(nextUnanswered);
    }, 1200);
  } else {
    // Принудительный стоп: раскрыть комментарий через 150ms
    setTimeout(() => setShowComment(true), 150);
  }
}, [answer, questions, current, answered, handleGoTo]);

const handleToggleComment = useCallback(() => {
  // Если открываем комментарий — отменяем авто-продвижение
  if (!showComment && autoAdvanceRef.current) {
    clearTimeout(autoAdvanceRef.current);
    autoAdvanceRef.current = null;
  }
  setShowComment(prev => !prev);
}, [showComment]);
```

Вспомогательная функция:
```javascript
function findNextUnanswered(questions, answered, current) {
  // Сначала ищем вперёд
  for (let i = current + 1; i < questions.length; i++) {
    if (!answered.has(questions[i].id)) return i;
  }
  // Потом назад (если впереди всё отвечено)
  for (let i = 0; i < current; i++) {
    if (!answered.has(questions[i].id)) return i;
  }
  return -1; // все отвечены
}
```

### E. Error Reinforcement System

**Проблема старой системы:** ошибка записывается в `qp_errors`, но пользователь видит её только при следующем заходе в /errors. Петля обратной связи = несколько дней.

**Новый механизм — Post-session error review:**

После нажатия VERIFICA (или когда `isFinished` → `true`) ResultScreen получает улучшение:

Под текущим блоком статистики добавляется раздел "Ваши ошибки" — список карточек для каждого неправильного ответа с:
- Текстом вопроса (первые 80 символов)
- Правильным ответом (VERO / FALSO)
- Первой строкой комментария (если есть)

Это не требует новых загрузок данных: `results` содержит `questionId`, `questions` уже загружены в память — lookup по `questionId` бесплатный.

```javascript
// В ResultScreen — дополнение
const wrongResults = results.filter(r => !r.correct);
const questionsMap = questions.reduce((acc, q) => {
  acc[q.id] = q;
  return acc;
}, {});
// wrongResults.map(r => questionsMap[r.questionId]) — уже доступно
```

**Внутрисессионный цикл (опционально, не для первой итерации):** после просмотра результатов кнопка "🔁 Повторить ошибки" запускает `useQuiz('errors:topicId')` — уже реализовано в системе. Это не новая логика, просто прямая ссылка из ResultScreen.

### F. Behavioral Design Principles

**Принцип 1: Принудительная рефлексия только при ошибке.**
Зачем: нарушение ожиданий (я думал VERO, оказалось FALSO) создаёт наивысший уровень внимания. Именно в этот момент объяснение усваивается максимально глубоко. Останавливать пользователя при правильном ответе — лишнее трение.

**Принцип 2: Авто-продвижение при правильном ответе.**
Зачем: reward — скорость. Правильный ответ = система "награждает" плавным продвижением вперёд. Это создаёт положительное подкрепление для знания материала.

**Принцип 3: Per-question перевод.**
Зачем: пользователь развивает метакогнитивный навык — "мне нужен перевод для этого вопроса или нет?" Это само по себе акт самооценки сложности, что улучшает retention.

**Принцип 4: Ограничение навигации к неотвеченным.**
Зачем: устраняет стратегическое поведение ("отвечу сначала на лёгкие"). Каждый вопрос требует честной попытки воспроизведения знания. Это maximizes retrieval practice — самый эффективно доказанный механизм долгосрочного запоминания.

**Принцип 5: Разбор ошибок встроен в ResultScreen.**
Зачем: ошибки свежи в памяти сразу после теста. Через час — гораздо менее. Встроенный разбор использует это окно.

## 3. КРИТИКА И СТРЕСС-ТЕСТ

---

### A. Анализ сложности

**Реальные добавления:**
- `autoAdvanceRef` + `setTimeout`/`clearTimeout` в QuizPage (~15 строк)
- `findNextUnanswered()` — утилита (~10 строк)
- CSS: progress-линия таймера — один `div`, одна анимация
- CommentAccordion: кнопка "Далее" внутри при `!isCorrect`
- ResultScreen: раздел ошибок (~20 строк JSX)
- Ограничение навигации: в `QuizPagination` — фильтр кликабельности

**Где добавляется трение для пользователя:**
- При ошибке: обязательно читать комментарий и нажимать "Далее". Это осознанное решение — добавляем трение только там, где оно педагогически оправдано.
- Нельзя "прыгнуть" к неотвеченному вопросу — потеря одной навигационной свободы. Для целевого пользователя (подготовка к экзамену) это плюс.

---

### B. Производительность (iPad mini 2)

**Риски:**
- `setTimeout` × 30 вопросов — нет риска, таймер один в момент времени, `clearTimeout` работает корректно
- CSS-анимация таймера: `width: 0 → 100%` за 1.2s — это `transform: scaleX` будет лучше (`will-change: transform`), так как не вызывает reflow
- Auto-раскрытие CommentAccordion: сейчас это просто `isVisible` prop → условный render. Никаких анимаций — OK для iPad mini 2
- Ограничение навигации в QuizPagination: добавляется проверка `!answered.has(q.id)` в onClick — O(1) lookup в Map, нулевая стоимость

**Рекомендация по progress-линии таймера:**
```css
.answer-timer-bar {
  height: 3px;
  background: var(--color-correct);
  transform: scaleX(0);
  transform-origin: left;
  transition: transform 1.2s linear;
  will-change: transform;
}
.answer-timer-bar.active {
  transform: scaleX(1);
}
```
Применять через `requestAnimationFrame` после setState — так браузер успеет отрисовать исходное состояние перед анимацией.

### C. Валидность обучения

**Вопрос: действительно ли происходит рефлексия?**

При ошибке: CommentAccordion открывается автоматически, кнопка "Далее" требует tap. Пользователь может нажать "Далее" не читая. **Это нельзя предотвратить полностью** без серьёзного overengineering (таймер обязательного чтения, eye-tracking и т.д.).

**Реалистичная оценка:** даже принудительное появление комментария перед глазами на 1-3 секунды (пока палец дотягивается до "Далее") лучше, чем текущая ситуация когда комментарий скрыт по умолчанию и требует отдельного действия.

**Вопрос: достаточно ли 1.2s паузы при правильном ответе?**

1.2s — компромисс. 800ms ощущается слишком быстро на медленном устройстве. 2000ms — раздражает при 30 вопросах (добавляет минуту к сессии). 1.2s создаёт ощущение "пространства" не блокируя поток.

### D. Edge Cases

---

#### D1. Speedrunning — пользователь жмёт очень быстро

Сценарий: пользователь нажал VERO, авто-продвижение запустилось (1.2s таймер), и до его срабатывания нажимает на кружок в пагинации чтобы перейти к другому вопросу.

**Проблема:** таймер сработает после перехода и перебросит пользователя на следующий неотвеченный, прерывая ручную навигацию.

**Fix:** `handleGoTo` должен делать `clearTimeout(autoAdvanceRef.current)`:
```javascript
const handleGoTo = useCallback((index) => {
  if (autoAdvanceRef.current) {
    clearTimeout(autoAdvanceRef.current);
    autoAdvanceRef.current = null;
  }
  setTransitionDirection(index > current ? 'forward' : 'backward');
  goTo(index);
  setShowComment(false);
}, [current, goTo]);
```

---

#### D2. Пользователь игнорирует комментарии

Сценарий: ошибся, CommentAccordion открылся, нажал "Далее" за 0.1s не читая.

**Оценка:** это осознанный выбор пользователя. Система не должна быть тюрьмой. Ошибка всё равно записана в `qp_errors`, появится снова в /errors. Принудительный таймер на чтение был бы хуже по UX чем педагогическая польза.

**Fix не требуется.** Достаточно что комментарий *виден* — даже периферийное восприятие лучше чем ноль.

---

#### D3. Пользователь регулярно ошибается на одних и тех же вопросах

Текущая система: `incrementError` накапливает счётчик, вопрос появляется чаще в /errors. Но пользователь не видит этот счётчик.

**Fix:** В ResultScreen, в разделе ошибок, показывать рядом с вопросом счётчик из `errorsService.getErrors()[questionId]` — "⚠️ 3-я ошибка на этом вопросе". Это создаёт осознание паттерна.

Реализация: `errorsService.getErrors()` — синхронный вызов, нет нагрузки. В ResultScreen добавляется один вызов после рендера.

---

#### D4. Лаг на слабом устройстве

Сценарий: iPad mini 2, загрузка изображения 3s, пользователь нажимает VERO пока изображение не загрузилось.

**Текущее состояние:** изображения `loading="lazy"` — это корректно. Нажатие на кнопку не зависит от загрузки изображения, `answer()` срабатывает немедленно.

**Риск нового решения:** CSS-анимация progress-линии. На Chrome 92 iOS `transition: transform` на `div` — безопасно. Риска нет если использовать `transform: scaleX` вместо `width`.

**Риск auto-раскрытия CommentAccordion через 150ms:** если JS-поток занят (например, загружает следующее изображение), `setTimeout(150ms)` может сработать позже. Это нормально — небольшая задержка перед раскрытием комментария не критична.

**Graceful degradation:** если таймер не срабатывает (экстремальный freeze) — пользователь просто остаётся на текущем вопросе с заблокированными кнопками. Нет data loss. Нет crash.

### E. Итоговые исправления по результатам стресс-теста

| Найденная слабость | Конкретный fix |
|---|---|
| Таймер не отменяется при ручной навигации | `clearTimeout` в `handleGoTo` |
| CSS анимация таймера вызывает reflow | Использовать `transform: scaleX` + `will-change` |
| ResultScreen не показывает детали ошибок | Добавить раздел с lookup по `questions` в памяти |
| Счётчик повторных ошибок невидим | В разделе ошибок ResultScreen показывать `errors[questionId]` |
| Кнопка "Далее" при ошибке — нет места в текущем CommentAccordion | Добавить внутрь CommentAccordion при `!isCorrect` prop |
| ConfirmationModal текст пугает насчёт потери прогресса | Исправить: "Отметки ошибок уже сохранены. Потеряются только результаты этой сессии." |
